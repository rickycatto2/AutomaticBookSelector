# Metadata boundary audit — 2026-10-11

Original audit scope: working trees of AudiobookFunnel, AudiobookApp and AutomaticBookSelector. Existing unrelated edits were preserved. That audit performed no live book/database mutations, scans, Goodreads uploads, deployment, security configuration changes, git commits/pushes or GitHub operations. The subsequent Selector commit review is recorded below.

## Verified path

* A read-only public Audible.com lookup for ASIN **B0GFB7WK22** returned author **Veronica Roth**, English, 960 minutes, and narrators **Emma Love / Charlie Thurston / Max Meyers**. The existing reduced Funnel fixture additionally records title *The Sixth Faction*. It also contains German edition B0HCW29JJZ with explicitly labeled translators and different narrators/runtime. This is catalog evidence, not proof of the identity of any local audio.
* Funnel `metadata.audible_product` excludes only names explicitly ending in ` - translator` (including en/em dashes and case variants) from `author`; ambiguous/unlabeled contributors and legitimate coauthors remain. Both direct-ASIN and search use it. `main.select`, `main.auto_match`, and `worker.inspect_pending` copy normalized fields; manual editing is separate and provenance is recorded. Existing stored flat candidates are **not renormalized**: rerun search and reselect/review old jobs.
* `media.process` creates a fresh MP4 with `-map_metadata -1`; `write_tags` writes **©ART = aART = author**, **©wrt = narrator**, album/title, and freeform ASIN/ISBN/language when known. Funnel reads album artist before artist, composer as narrator. `reader.html` is a human-readable escaped metadata view, `funnel.json` is metadata/provenance/hash, and `desc.txt` is description only. None is an ABS contributor override.
* ABS **v2.36.0** source was fetched read-only and inspected; this is the version used in AudiobookApp's reference docs, **not a verified installed image/digest**. `server/utils/prober.js:164–227` reads artist, album_artist and composer separately. `server/objects/metadata/AudioMetaTags.js:151–175` maps these to tags. `server/scanner/AudioFileScanner.js:221–350` maps **Artist first, Album Artist fallback -> authors; Composer -> narrators**, and parses both name lists with `parseNameString`. The current Funnel atom fix therefore addresses ABS's actual preference, not just Funnel's roundtrip preference.
* ABS `Library.defaultMetadataPrecedence` is `folderStructure, audioMetatags, nfoFile, txtFiles, opfFile, absMetadata`; `BookScanner` executes sources in order and later sources overwrite populated keys. `AbsMetadataFileScanner` reads local `metadata.json`, or `/metadata/items/<id>/metadata.json` for existing items. `txtFiles` reads **reader.txt**, not Funnel's **reader.html**. Preexisting ABS metadata/OPF/NFO/reader.txt or custom precedence may still override good atoms.
* ABS `Book.authorName` joins the author relations with commas. Selector `Store.sync` keeps that full string (or authors-array fallback), ISBN and separate narratorName. BookRamp `AbsParser.book` likewise uses authorName/authors, not narrators, and does not decide Goodreads mappings. Android's current tree removes its old Goodreads exporter; the reviewed public CSV path is Selector.
* Selector Goodreads review starts **unconfirmed**; valid ISBN + explicit confirmation + completion date + title/author are required. CSV uses the **reviewed author and ISBN**, not `author_key`, narratorName, private feedback or an automatically guessed print edition. ISBN checksum validates syntax, not bibliographic identity.

## Focused fixes in this audit

1. Funnel rejects non-identical normalized author evidence as an automation conflict, including when filename evidence would otherwise hide an extra embedded author. A high fuzzy score no longer permits coauthor loss, even at a lowered threshold.
2. Selector's prior `canonical_author` heuristic collapsed a multi-name identity to one Goodreads/preferred-author component, without role evidence. It now preserves the complete normalized identity. The old regression expecting assumed narrator removal was corrected: questionable entries remain for review instead of silently sharing read-history/author affinity. Raw display/export author was already preserved.
3. Selector ISBN normalization now validates ISBN-10 before converting to ISBN-13 and validates ISBN-13 checksum. Invalid ISBN-10 no longer becomes a manufactured valid ISBN-13; malformed X placement cannot crash conversion.
4. Goodreads page lookup rejects multiple distinct usable Book/ISBN candidates instead of picking the first nested Book (possibly a related title). Exact repeated nodes are deduplicated. It never auto-confirms.
5. Confirmation/skip flags must be actual booleans, not truthy strings. Editing title/author/ISBN/link clears the UI's existing confirmation. Removed misleading “Any edition is fine” language; review explicitly includes work, author roles, language and ISBN edition, without encouraging removal of coauthors.

## Remaining boundaries / manual review required

* **No real ABS scan was run.** Verify installed version/digest, library metadata precedence, existing item metadata/locks and any later provider match before claiming published tags repaired ABS records. ABS provider quick-match can independently change authors when overrideDetails is enabled. A source-only function harness is not that scan.
* **Funnel selection copies only nonempty candidate fields.** Switching candidates can retain an ISBN/ASIN/language from an earlier candidate when the new candidate omits it. Review all final identifiers/edition fields and provenance; clear stale ones manually. No automatic cleanup/migration was attempted in the concurrently edited Funnel selection workflow.
* **Funnel auto-match checks embedded evidence, but preserves Manual fields.** A manual edit diverging from the winning candidate can be queued while the eligibility explanation still describes the embedded/candidate match. Do not treat eligibility as validation of all edited final metadata; use explicit final review. A future fix should reconcile final/manual evidence rather than overwrite deliberate edits.
* **Explicit translator attribution is not separately retained** by the current flat Funnel schema. Excluding an explicitly labeled translator from authored credits prevents false authorship, but translated editions need manual role/credit preservation (description or reviewed sidecar) until a dedicated contributor-role path exists. Ambiguous roles are intentionally not stripped. No translators occur in the selected English ASIN response.
* **Selector confirmations are keyed to ABS item ID, not an immutable source-metadata snapshot.** Previously confirmed export details can survive a later sync changing that item's title/author/ISBN. Re-review or clear confirmation after metadata changes; a future source fingerprint/invalidation migration is needed. Existing saved confirmations/exports were not modified.
* `identity` intentionally collapses title decorations/subtitles, and Goodreads review deduplicates/excludes by title key alone. Separate same-title works, translations, abridgements or editions can be hidden/excluded; review manually rather than interpreting exclusions as bibliographic proof. A future identity-schema change should be reviewed independently.
* Unlabeled translators/narrators in upstream author fields cannot be safely inferred away from a known-author list. Wrong upstream authors will remain visible until reviewed. Name parsing in ABS is heuristic (commas/semicolons/and/&), so unusual personal names and ambiguous multi-role credits also need manual inspection.
* Goodreads structured metadata is only a suggestion. A single related Book node could still be the only usable node; the caller must compare it with the intended work. No real Goodreads edition/ISBN for this Roth audiobook was established, and no upload was attempted.
