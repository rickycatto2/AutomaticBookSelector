# Reviewed Goodreads exports

**Goodreads export** lists completed ABS/BookRamp books absent from the imported Goodreads read history. DNF, ignored, already exported and duplicate editions are excluded. The original Goodreads seed is retained. Previously imported to-read entries can supply a candidate edition/full author list; these remain unconfirmed until reviewed.

Review title, all authors/roles, an ISBN for the same work, the actual date completed, and optional **public** stars. Private feedback is never copied into this table and public stars never train recommendations. Per user preference, a correct print/Kindle/large-print/translated edition is acceptable; exact language/edition is not required. ISBN-10 leading zeros and X check digits are preserved, and ISBN-10/13 checksums are validated. Dates from ABS millisecond/ISO timestamps are converted to America/Chicago. Missing/future completion dates block exports until you enter the genuine date; a sync/import date is never substituted. **A valid checksum or external catalog listing does not guarantee Goodreads will import an ISBN.** Use a one-book manual import and return failures below.

## Bounded automatic check and explicit free catalog action

Loading the Goodreads list automatically checks **at most one undecided book** using free catalogs (Google Books optionally uses a server-side quota key; see below). The server caps this at **ten books per rolling 24 hours per process**, and spaces attempts by at least five seconds. Each book can make at most two provider requests. Concurrent loads do not multiply requests; list loading never starts a per-card loop or automatic retry. Restart resets these in-memory budget/pacing bounds, but attempted source fingerprints (including uncertainty/errors) now persist in additive tables and prevent automatic/batch repeats across restarts. Existing saved decisions and failed imports are never searched automatically. The UI does not replace unsaved edits after a slow check. High-confidence evidence can save an ISBN and make the book ready without another action; uncertain metadata remains in review with the reason displayed.

### One-click matching of eligible completions

**Match eligible books** explicitly creates or resumes a durable queue of **at most 25 eligible completed ABS books** from this export review list, not the Goodreads seed (even if that seed contains thousands of entries). Existing saved/manual/failed decisions and previously attempted source fingerprints are excluded. Queue creation makes no provider calls. The browser calls the existing `/api/goodreads/resolve` with **one book per request** plus the queue ID; it waits five seconds before each request, including the first and after each completed response. The existing server-side per-provider throttle remains authoritative. Each request has at most two bounded provider calls, avoiding one long Cloudflare request for the entire batch. Progress shows ready, review, skipped and provider-error/interrupted counts.

**Pause matching** stops before the next request. A request already in flight may finish and persist its result. Closing the page starts no further requests; reopening shows the saved queue and resuming requires another button press. The queue cannot grow during resume. An attempt is claimed durably before lookup: duplicate/concurrent requests or interrupted requests are never silently repeated. An interrupted attempt stays review-only; use the existing per-book explicit resolver to retry deliberately. Provider errors and throttle results are retained, not automatically retried. Source/decision/export changes while paused cause queued items to be skipped; they do not overwrite existing decisions. Finishing a queue permits a new explicit queue only for still-undecided, previously unattempted books.

Low-confidence candidate suggestions, ambiguous catalog evidence and reasons persist across refresh/restart and are displayed separately from the user's saved form. They do not confirm a book or overwrite saved fields. Copy/review suggested details (or use the per-card resolver), confirm, and save manually. Unknown/different language is neutral and labeled an edition difference; conflicting authors/work identities and unlinked Open Library ISBNs remain review-only. Missing dates are never invented. The batch refuses to start with unsaved edits and makes book forms inert while running; pause to edit. No ABS writes, paid calls or Goodreads uploads are introduced. Existing export and failed-import reconciliation actions remain explicit.

Synthetic browser regression: serve `tests/test_goodreads_batch_browser.html` and `static/` on loopback, open the test page, and require its **PASS** result. It uses real DOM elements, a virtual five-second clock and a fake durable API to cover progress, rate, 25-book cap, pause while waiting/in flight, page-close resume and all counts; it never loads a user database or contacts catalogs.

**Find work ISBN (free catalogs)** remains available explicitly. Both paths send the synced source title and complete author string to Google Books, then Open Library if Google is unavailable, has no exact work, or lacks a valid ISBN. Google Books is anonymous unless optional `GOOGLE_BOOKS_API_KEY` is set in the private `.env`/server environment; that credential is sent only to Google server-side, never to the browser or Open Library. No paid services, reviews, ratings, descriptions, reading state, dates, or ABS credentials are sent. Nothing is uploaded to Goodreads. Searches operate on synced source metadata, not unsaved form edits.

Provider failures show only provider, status and a safe explanation, not response bodies or request URLs. HTTP 429 suppresses that provider until the next UTC day boundary locally (not a promised provider reset); transport/timeout failures use a 60-second backoff. Restart or a changed provider credential clears that in-process cooldown; the five-second spacing still applies. Durable attempt records remain. **Retry provider-blocked books (up to 25)** explicitly creates a one-book-per-request queue only for quota/transport failures without candidates, saved decisions or failed imports. It does not erase attempts or retry review outcomes. Provider-blocked cards say lookup could not run and remain blocked from export.

Evidence score is 0–100, with auto threshold **90 plus linked ISBN identity**: exact normalized work title +40 (conservative one-sided subtitle match +35), independently corroborated full author set +35, checksum-valid catalog ISBN +15, linked edition identity +10. Language is neutral (+0). Explicit format/numbered-series suffixes may be ignored; subtitle matching requires a non-generic base of at least three words and twelve characters and never discards two conflicting subtitles. There is no fuzzy/generic title matching. Same-title author conflicts, conflicting subtitles and explicit uncertain contributor roles require review; fallback never launders conflicts. A truncated provider page does not force review on its own, because broad correct queries routinely report totals far above the ten-result page: a truncated page may auto-confirm only when every matching candidate agrees on one exact work title key and the full source author set, with no conflicting subtitle or volume marker among them and a checksum-valid ISBN on every candidate. If those candidates disagree on work title, author set or subtitle/volume markers, or any of them lacks a usable ISBN, truncation still forces review, and a relaxed match states in its reason that the search was truncated yet unanimous. Narrator==author is allowed only with independent catalog corroboration of the complete author set, not by stripping names. Multiple Google volumes with the same normalized work/full authors may auto-confirm; selection is deterministic, preferring publisher/print evidence, then ISBN-13 and stable ISBN/ID ordering. These are evidence scores, not calibrated probabilities or proof of Goodreads acceptance. Unsafe fields and duplicate candidate work/ISBN in prior read/export records prevent automation; existing saved/failed decisions remain untouched.

Open Library aggregated **work-level** ISBNs remain suggestions only. Auto-confirmation requires a unique valid work ID with full author evidence and an included edition record with its own book ID, matching work/full author set, and checksum-valid ISBN. The two-provider/two-request ceiling is unchanged: no additional edition fetch is launched. If search does not expose this evidence (as is common), review remains required. Multiple distinct work IDs block selection. No language inference or source corrections are required.

Transport uses fixed HTTPS endpoints `www.googleapis.com/books/v1/volumes` and `openlibrary.org/search.json`, TLS verification, disabled environment proxies, no credentials/cookies/redirects, 10-second timeout and a 1 MB response cap. Searches are capped at ten records. Each provider permits one uncached request per five seconds; a 128-entry in-memory cache lasts 24 hours. `/api/goodreads/resolve` accepts 1–10 distinct queued ABS IDs, processes sequentially, and returns rate-limited items for review rather than sleeping or launching unbounded retries. `/api/goodreads/auto-resolve` implements the tighter automatic bounds above with the same authentication/origin protections. Export/download still requires the explicit existing export button; there is no automatic upload/download.

Existing manual/automatic/failed decisions are never overwritten by resolution. Saved matches retain a separate source-metadata fingerprint (ABS ID/title/full author/ISBN/language/narrator) and provenance/evidence. Changed source metadata or legacy matches with no fingerprint block readiness while retaining all old match records. Reload and explicitly re-review/save to bind them to the new source; an open UI form's old fingerprint is rejected after a concurrent sync. Legacy confirmations are not destructively migrated. Failed imports remain unconfirmed and are never automatically retried.

Export/history/queue dedup uses normalized work title plus full author set, checksum-valid ISBN equivalence, and prior exported ABS IDs. Existing export rows/CSVs/states are unchanged. Same-title different-author works remain visible unless they share an already-read/exported ISBN. Identically named same-author works cannot reliably be distinguished without additional evidence; this increment does not reclassify historical editions.

The CSV has `Title,Author,ISBN,My Rating,Date Read,Shelves`. Date Read is always present and nonblank, in YYYY-MM-DD format, and Shelves is always read. The generator quotes commas/newlines through the standard CSV writer and delivers UTF-8 with BOM from the browser. Goodreads may accept fields differently for existing reviews and rereads; one-book testing is still necessary. There is no supported guarantee that a CSV creates social-feed entries.

**Find Goodreads match** opens a title/author web search. **Find print/ebook edition** opens the same external Google search with paperback/hardcover/print terms added, because an audiobook page (identified only by an ASIN) often ranks first otherwise. Both are plain `site:goodreads.com/book/show` searches built with percent-encoded form values; nothing is crawled and no request goes to Goodreads. Paste a Goodreads book URL and press **Get ISBN from link** to retrieve structured ISBN metadata from the public book page. It is a bounded, explicit, rate-limited request, with no Goodreads credentials, redirects, proxy rotation or challenge bypass. Search crawling is not implemented because Goodreads' robots.txt disallows `/search`. An ASIN-only audiobook page has no ISBN to extract; the lookup then says so and points you to **Find print/ebook edition** or **Find work ISBN (free catalogs)**. Any page without a usable ISBN (often a Kindle edition) needs Book details & editions on a print edition, with the ISBN copied manually. When the form's ISBN passes the checksum, **Open Goodreads edition for this ISBN** appears as a direct `https://www.goodreads.com/book/isbn/<ISBN>` link; this is only a convenience redirect — a valid checksum never asserts that Goodreads recognizes or imports that ISBN. Fix narrator-filled ABS authors in the export form; this does not rewrite ABS metadata.

When you export, the batch CSV and its item records are saved atomically and the items are marked **exported** immediately. Subsequent batches contain only new/failed works. **Download again** reuses the saved batch if a browser download fails. Goodreads import confirmation is separate from export state.

Paste Goodreads' output into **Preview import result**, inspect the per-book states/reasons and proposed failures, then **Save reviewed import result**. Mixed reports are supported conservatively: a success line never becomes an inferred failure. Detection recognizes Goodreads' `1 book could not be imported:` / `ISBN<TAB>Title<TAB>Author` table (including blank Title), explicit leading failure statuses (`Failed:`, `Could not import:` etc.) or a `Failed books` section. It requires an exact checksum-valid ISBN token (ISBN10/13 equivalents count) or a whole `Title by Author` payload, not substrings. Table count mismatches, unsupported formats, missing context, shared ISBNs and conflicting statuses require explicit per-book selection. **Choose failed books manually** is always available; selections use ABS IDs, not titles. Manual selections cannot silently erase detected failures. A selected book with a recognized success line is rejected until the contradictory report/selection is corrected.

Failed items alone return to review with confirmation cleared, requiring a corrected match before retry. Only explicit boolean confirmation can mark other still-exported rows imported, and only after identified failures/successes or explicit nonempty per-book failure selection resolve ambiguity. Empty input is a no-op; unknown text alone never imports the remainder. Historical CSVs/IDs are retained; reprocessing an old failed result does not clear a newly reviewed match again, and an old batch cannot invalidate a newer retry export. Reasons are stored/displayed per book, bounded to 500 characters; the whole pasted report is not stored. Reconciliation has no network calls and does not access private feedback. Nothing is uploaded to Goodreads by this app.

## Gouged failed-file investigation

A test row for *Gouged* used 14 headers/14 values, valid audiobook ISBN `9798217356157`, a populated Date Read, and Shelves `read`. It was not missing a completion date and no CSV column shift was found. Goodreads' rejection does not establish an exact cause. An unrecognized audiobook edition is a plausible explanation.

The publisher lists a print edition of *Gouged: The End of a Fair Price—and What That Means for Your Wallet* by Lindsay Owens with ISBN **9798217058785**. The app's public-page lookup succeeded for https://www.goodreads.com/book/show/241504373 and retrieved Goodreads-listed ISBN **9781399633413**, the full title, and Lindsay Owens as primary author. This gives a Goodreads-listed identifier to try instead of an unrecognized audiobook ISBN. Review the completion date from ABS before exporting; it can differ from an earlier manually prepared file. CSV acceptance, challenge count and feed behavior still require a real manual import. Test CSVs and personal completion dates are kept outside the repository.
